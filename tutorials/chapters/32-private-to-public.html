Level 3 · Bitcoiner · chapter 32

32 Private key → public key

Level 3 · Bitcoiner. A private key is a number k with 1 ≤ k ≤ n − 1; its public key is the point kG. You will type keys as kG, read the public key in every encoding, and see how keys add. Read first: 31 secp256k1 in the panel.

The visualizer reads kG (also k*G, k·G, (expression)G, -G, λG) as “k times G”. It computes the point with Jacobian double-and-add and remembers the k you typed, so the cards show it. Only use keys that are made up: these tutorials use small numbers and visibly made-up patterns, never anyone’s real key.

Do it yourself

  1. In Curve, pick the preset secp256k1: G and −G (mirror pair).
  2. Type 3G in P₁.
  3. Empty P₂.
  4. In the 3D view, click P₁ to pin its card.
  5. Read the Inspector section in the panel.

Look at: the card of 3G says k = 3; the Inspector’s SEC 02/03 row is its compressed public key. The table gives keys 1 to 5; each public key was computed by idleCore and by OpenSSL, and checked in the visualizer.

Why: these five keys are well known precisely because they are trivial: anybody can compute them, so they must never hold funds. 1G is G itself.

Example 32.3 · The last key: (n − 1)G = −G

Open this view: (n − 1)G and G

Do it yourself

  1. In Curve, pick the preset secp256k1: G and −G (mirror pair).
  2. Type (n-1)G in P₁ and G in P₂.
  3. Press 3 for the side view.
  4. In the 3D view, click P₁ to pin its card.
  5. Read the Relations section in the panel.

Look at: Relations: P₁ vs G “P₁ = −G, the mirror of G”, P₂ = −P₁ yes, and the sum 𝒪.

Why: nG = 𝒪, so (n − 1)G = −G. Private keys k and n − k always give mirror images: the same x, opposite parity of y, the prefixes 02 and 03. Here n − 1 = fffffffffffffffffffffffffffffffebaaedce6af48a03bbfd25e8cd0364140.

Why: k₁G + k₂G = (k₁ + k₂)G, with the sum taken mod n. Here k₁ + k₂ = 2²⁵⁶ − 1, which is larger than n, so the card shows (2²⁵⁶ − 1) − n = 000000000000000000000000000000014551231950b75fc4402da1732fc9bebe. This linearity is what BIP32 derivation and Taproot tweaks build on (37 Where points appear in Bitcoin).

Example 32.5 · k is read mod n

Open this view: (n+5)G

typed in P₁ the point open
(n+5)G 5G open
5*G 5G open
0x5G 5G open
-G −G, which is (n − 1)G open
nG 𝒪: nothing to draw open

Do it yourself

  1. In Curve, pick the preset secp256k1: G and −G (mirror pair).
  2. Type (n+5)G in P₁.
  3. Empty P₂.
  4. In the 3D view, click P₁ to pin its card.
  5. Read the Points section in the panel.

Look at: (n+5)G is the same point as 5G; its card says k = 5. The table shows other spellings: 5*G, 0x5G, -G (k = −1, the point −G) and nG, which is 𝒪: nothing to draw.

Why: n·G = 𝒪, so only k mod n matters. A wallet must reject k = 0 and k ≥ n as private keys; the visualizer, being a calculator, just reduces.

Try it yourself

  • Type 2^255G: a power of two as a key. Which prefix does its public key get?
  • Type (n-1)/2 G: is the result’s x the same as for (n+1)/2 G?
  • Put the same made-up key into P₁ and G into P₂, and press N a few times: the card’s k counts up from it.

Recap

  • A public key is kG; the visualizer reads kG with any integer expression for k and keeps k on the cards.
  • k and n − k give mirror images; k is taken mod n.
  • k₁G + k₂G = (k₁ + k₂ mod n)G: public keys can be added without knowing the private keys.
