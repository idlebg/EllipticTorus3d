# Architecture

How `elliptic_curve_torus_visualizer_v3.html` is put together: where the code lives, how a change in the panel
reaches the screen, and the rules the rendering depends on. For using the page, see the [README](../README.md).

## Build

One HTML file that runs from `file://` with no network: no CDN, no fetch, no web fonts. `build.mjs` bundles the
few three.js symbols the app uses (`src/vendor-entry.js`, tree-shaken by esbuild into the IIFE global
`VENDOR_THREE`, minified) and concatenates the app files, `export` stripped, into the template `src/index.html`:

```sh
npm ci            # three@0.187.0 and esbuild@0.28.2, pinned in package-lock.json
node build.mjs    # writes elliptic_curve_torus_visualizer_v3.html (or: node build.mjs out.html)
```

The app code stays readable inside the HTML; only the vendor block is minified. Never edit the built HTML: edit
`src/` and rebuild. The build is byte-for-byte reproducible from the sources and the lockfile, as long as the files
keep LF line endings (`.gitattributes` makes git keep them on Windows too). There is no `eval` or `new Function`:
everything typed by the user goes through the expression parser `evalExpr` in `src/engine.js`.

## Data flow

`S` (the persisted UI state) → `computeModel(S)` → `M` (curve, facts, parsed inputs, `targets` with turn
coordinates, operation result, chord, relations) → `renderPanel()` + `buildTorus()` / `buildCloud()` /
`buildMarks()` (rebuilt only when their key changes) + `rebuildOverlay()` + `resolveTargets()` (re-attaches hover
and pins by key) + `drawMini()`. `update()` runs that chain; text fields debounce it (280 ms), Enter runs it at once.

- `computeModel` never throws: errors land in `M.curveErr`, `M.inputs[k].error` or a relations row.
- Panel writes go through `setHTML` / `setText`, which skip unchanged content (no relayout, no aria-live
  re-announcement).
- The model only knows turns (u, v) = (x/p, y/p). The shape is applied in the view (`surfPoint`), so
  `computeModel` and the flat map do not depend on it.
- A shape change from the tiles or `S` does not call `update()` at first: `setShape` → `startMorph` blends the old
  shape into the new one for 0.7 s, then `loop()` ends the morph and calls `update()`. Any `update()` during a
  morph ends it at once. `ecTorus.set({ shape })` goes straight through `update()`, with no morph.
- State travels in `localStorage` and in `#s=` links (base64url JSON). Everything read back goes through
  `sanitizeState`: known keys only, typed and clamped, ids checked against the known presets and shapes.

## Rendering

The technical-drawing look depends on these rules.

- **Hidden lines.** An invisible depth mask (the surface pushed a hair inward, `colorWrite: false`, renderOrder 0)
  is drawn first. Everything else is drawn twice: normally, and again with `depthFunc = GreaterDepth`, dashed and
  faint, which only passes behind the mask. That second pass is the "hidden lines" slider.
- **Order.** Lines and sprites have `depthWrite: false`; ordering is by `renderOrder`: hidden pass 2–3, glass shell
  4, mirror disc 5, grid 8, cloud 9, rings 12–19, chord 22, mirror segment 23, markers 29–31, selection 40.
- **Markers** are sprites with `sizeAttenuation: false`; scale = 2·px / (projection[5] · viewH), refreshed on resize.
- **Fat lines** (`Line2` / `LineSegments2` with `LineMaterial`, width in CSS px). On software WebGL (SwiftShader,
  llvmpipe) the grid falls back to 1-px GL lines; `?lines=thin|fat` overrides the choice. Every fat line goes
  through `strokeOnce()`: the renderer has a stencil buffer and each line object takes a fresh stencil id (1…255,
  NOTEQUAL / REPLACE) in `onBeforeRender`, so a line blends at most once per pixel (the round caps of neighbouring
  segments overlap at every joint) while different lines still blend over each other. Measured: the integrated
  ring width equals the spec (1.90 / 2.60 CSS px) at DPR 1, 1.5 and 2.
- **Glass.** A fresnel shell (denser edge-on) with, on the dark theme, a Blinn glint from a fixed view-space key
  light, scaled by the glass slider. The paper theme has no glint, so it keeps the reference plate's flat look.
- **Transparent canvas** (`alpha: true`, clear alpha 0), so the CSS background shows through; PNG export sets
  `scene.background` for one frame.
- **On-demand rendering.** `loop()` renders only when the controls report motion, a camera tween or morph runs,
  or `view.dirty` is set: idle means zero frames. `afterRender()` repositions overlay labels and cards.
- **Material disposal is deferred.** `disposeGroup()` retires materials and `loop()` disposes them after the next
  render: three.js deletes a shader program when its last material is disposed, so disposing before rebuilding
  relinked three to five programs on every update.
- **Pixel ratio.** `resizeView()` also sets the pixel ratio, and a `(resolution: Ndppx)` media query re-arms
  itself, so browser zoom and moves between monitors keep the canvas sharp.

### Shapes

- A point's turns go through `patchST` (a cut direction is centred: t = (v + ½) mod 1, so y = 0 lies on the mirror
  plane) and the shape's `pos`, lifted along its `nrm`.
- Negation, t ↦ 1 − t, must be the reflection through the shape's `mirror` plane, normals included, so lifted
  rings and markers stay mirror images. The trefoil is chiral and has no mirror plane (`mirror: null`); there
  t ↦ 1 − t is the reflection inside each ring, through the ring's centre with normal along
  P(s, ¼) − P(s, ¾). `test/shapes.test.mjs` and the self-test check both.
- Lines come from `curveSegs`, which drops segments that cross a cut (`cutU` / `cutV`) and zero-length ones (poles).
- Open or one-sided shapes (cylinder, wavy plane, Klein bottle) draw the mask and the glass from both sides; the
  collision mesh used for occlusion is always double-sided. The torus keeps `TorusGeometry` with its exact numbers
  (the camera is framed on R + r exactly, never on the float32 mesh).
- The trefoil is C(θ) = ((A + B cos 3θ) cos 2θ, (A + B cos 3θ) sin 2θ, B sin 3θ) with A = R and B = 0.45·R, where
  the knot is thickest (half its closest strand distance is 0.447·A, its smallest radius of curvature 0.738·A).
  The tube of radius 0.42·r is framed by the torus normal at C, which is perpendicular to the knot because the knot
  lies on the torus; it stays embedded over the whole slider range.
- **The morph** samples both shapes on one (s′, t′) grid whose t′ edge is where every cut lies (`morphST`: t′ is the
  patch t of a cut shape, (t′ + ½) mod 1 of a periodic one), so no sampled line crosses a cut and every sample has a
  partner on the other shape. It blends surface, depth mask (double-sided while it runs), grid, rings, markers
  (cards follow `t.pos`), curve points and axis labels in place; the chord, mirror disc and selection are hidden
  until the real build. `occluded()` answers false meanwhile, since the collision copy is the old shape. Reduced
  motion skips the morph.

## Testing

| suite | what it holds |
| --- | --- |
| `npm test` | `engine.test.mjs`: the engine against `ref_out.json` (point-set hashes, order histograms, 2-torsion, discrete logs, leading-zero SEC points, OpenSSL multiples, parser edge cases); `shapes.test.mjs`: every shape from its definition (finite, unit normals perpendicular to the surface, negation as a reflection, seams, the icosahedron's faces, the trefoil's knot type and embedding). Seconds, no install |
| in-page self-test | 42 checks shipped inside the page (Self-test section, or `ecTorus.selfTest()`) |
| `test/interact.py` | end-to-end over every control, zero console errors allowed (`npm run e2e`) |
| `test/robust.py` | hostile links and storage, `sanitizeState` fuzz, inputs that must not freeze the tab, GPU memory over 50 cycles, WebGL context loss and restore, DPR changes |
| `test/nowebgl.py`, `test/browsers.py` | the page without WebGL; WebKit / Firefox / Chromium |
| `test/hw.py --gpu`, `test/perf.py` | real-GPU renderer, hover frame times, line and marker widths per DPR, PNG export; timings |
| `test/showcase.py` | rebuilds `samples/`, checking every caption's claims against the live model first |

Every Playwright script shares `test/_launch.py`: by default Playwright's Chromium, headless, with SwiftShader
(`--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`, since headless Chrome has no WebGL
without them); `--gpu` runs the installed Chrome, headed, on the real GPU; `--browser=firefox|webkit`;
`--html=path` runs a script against another build. Each logs the WebGL renderer it got.

## Pitfalls

- three.js writes `window.__THREE__ = "187"` as a duplicate-import guard, so the vendor global is `VENDOR_THREE`,
  never `__THREE__`.
- Author CSS `display` beats the `hidden` attribute; `[hidden] { display: none !important; }` is in the CSS.
- The app is an inline `type="module"` placed before the vendor `<script>`; modules are deferred, so the vendor
  runs first. Keep that order, and keep `</script>` out of both blocks.
- `GreaterDepth` is 6 in three's constants (5 is `GreaterEqualDepth`).
- `PointsMaterial.alphaTest` must stay tiny (0.01): faint hidden-pass opacities fall under larger thresholds.
- The chord is drawn as a continuous line only when the centred |λ| ≤ 24, else the coil hides the surface; the flat
  map shows its p lattice points instead (p ≤ 4000).
- A BigInt `**` can build a 10⁹-bit number for seconds before any size guard sees it: check the size first.
- A compressed SEC key names the curve point with that x. Points the app writes back into a field or copies go through
  `pointText` / `encodeSECExact`: compressed only on the curve with p prime, `04…` otherwise (an off-curve point
  written compressed reads back as another point, and a composite p refuses compressed input).
- `history.replaceState` on `file://` and `localStorage` can throw; both are wrapped.
- The `#glfail` notice covers the whole stage: it must keep `pointer-events: none` or the flat map dies without
  WebGL.
- Textareas autosize only while visible; a collapsed `<details>` section hides its controls from Playwright clicks.
- After a shape change through the UI, wait for `!ecTorus.debug.view.morph` before reading positions or counting
  GPU objects: mid-morph, `t.pos` is a blend and the morph group holds extra buffers.
- Headless SwiftShader is far slower than a GPU on fat lines; slow hover in tests is the rasteriser, not JS.
  Chrome's `gl.finish()` does not wait for SwiftShader, so timed renders look cheap there.
- Headed (`--gpu`) runs: a freshly opened window may deliver no animation frames for a while, and hover is
  handled on the next frame; bring the page to the front and wait for a frame before hovering.
- CDP `Emulation.setDeviceMetricsOverride` changes `devicePixelRatio` but fires no media-query, resize or
  ResizeObserver event; `test/robust.py` calls the app's own listener to cover the monitor-move path.
